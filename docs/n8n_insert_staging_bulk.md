# إدراج staging بنداء واحد بدل آلاف النداءات

## المشكلة (اتشخّصت 2026-10-26)
عقدة `Insert Staging (دواء)` في وركفلو سان: داخلها **11,003 عنصر**،
وخارجها **صفر**. العقدة مش بتخلّص، فـ`Input 2` في `Merge (wait for both)`
عمره ماوصل، فـ`Merge` فضلت مستنية للأبد و`Swap Tables` ماشتغلتش أصلًا.

**وده مابيعدّش خطأ عند n8n** — كل العقد تفضل خضرا والتنفيذ «ينتهي»
من غير تبديل. النتيجة: `stock_san` اتجمّد من 10-25 14:10 (٢٧ ساعة)
والشاشات بتقرا رصيد بايت، وماحدّش حس.

**السبب**: وضع `Map Each Column Manually` بيبعت **سطر واحد في كل نداء**
— يعني 11,003 رحلة ذهاب وعودة للقاعدة.

## الحل: استعلام واحد
بدّل العقدة من `Insert` لـ`Execute Query` بالإعداد ده.

**Operation**: `Execute Query`

**Query**:
```sql
insert into public.stock_san_staging
select (jsonb_populate_record(
          null::public.stock_san_staging,
          e || jsonb_build_object('updated_at', coalesce(e->>'updated_at', now()::text)))).*
  from jsonb_array_elements($1::jsonb) e;
```

**Options → Query Parameters**:
```
{{ [ JSON.stringify($input.all().map(i => i.json)) ] }}
```
⚠️ **الأقواس المربعة إلزامية.** الخانة دي موصوفة في توثيق n8n بإنها
«قائمة قيم مفصولة بفواصل»، والتعبير اللي بيرجّع **مصفوفة** كل عنصر
فيه بيبقى معامل واحد. من غير `[ ]` الـJSON (المليان فواصل) بيتقسّم
لآلاف المعاملات والاستعلام بيقع.

**Settings → Execute Once**: ✅ **لازم تتفعّل**
من غيرها n8n هينفّذ الاستعلام 11,003 مرة (مرة لكل عنصر) ويدرج
كل الصفوف في كل مرة.

**Settings → Always Output Data**: ✅
ضمانة إن العقدة تطلّع عنصر حتى لو مرجّعتش حاجة، فالـMerge ماتعلّقش
تاني بنفس الطريقة.

## ليه ده أأمن
- `jsonb_populate_record` بيطابق بالاسم على أعمدة الجدول:
  الأعمدة الزيادة اللي جاية من eplus (`itm_scientific_n1`،
  `itm_effective`، `itm_active`، `sg_name_en`، `itm_group1/2/3`)
  **بتتجاهَل لوحدها** — فمفيش خريطة أعمدة يدوية تبوظ لما eplus يزوّد عمود.
- الأرقام غير المنصّصة بتتحوّل نص لوحدها، و`updated_at` ISO بيتقرا صح.
  (اتأكد بعيّنة حقيقية 2026-10-26.)
- العقدة بترجّع عنصر واحد، فـ`Merge` بتكمل و`Swap Tables` بتشتغل.
- لو الإدراج وقع، بيقع **بصوت** — مش بيفضل ساكت.

## بعد التعديل: التأكيد
لو التبديل تمّ، **`stock_<فرع>_staging` بيختفي** (بيتحوّل للجدول الحي)
و`stock_<فرع>` تاريخه يبقى النهاردة. لو الـstaging لسه موجود يبقى
لسه فيه حاجة واقفة.

## يتطبّق على
العقدتين في كل فرع (كوزمو + دواء) — بس غيّر اسم الجدول:
`stock_san_staging` / `stock_mamora_staging` / `stock_bishr_staging` /
`stock_seyouf_staging`.
ولو لزقت العقدة في الكانفس، اربط `Code → العقدة → Merge Input 2`
بإيدك — الوصلات مابتيجيش مع اللزق.

## ناقص كمان
تنبيه لو `max(updated_at)` لأي جدول مخزون بقى أقدم من ٦ ساعات.
الوقوف الصامت ده يتكرر في أي فرع، والفرق بين «اتكشف في ساعة»
و«اتكشف بعد يوم» هو التنبيه ده.

# قائمة التطبيق على باقي العقد

اتعمل: **سان / دواء** ✅ (2026-10-26، نجح من أول تشغيل).

الباقي ٧ عقد، كلهم نفس التلات خطوات:

| الفرع | العقد الناقصة |
|---|---|
| سان ستيفانو | كوزمو |
| المعمورة | كوزمو + دواء |
| سيدي بشر | كوزمو + دواء |
| السيوف | كوزمو + دواء |

## الخطوات لكل عقدة
1. **قبل ما تغيّر أي حاجة**: اقرا اسم الجدول من خانة `Table`
   في العقدة نفسها واكتبه. ماتعتمدش على التخمين — كل فرع جدوله باسمه.
2. `Operation` → **Execute Query**، والصق الاستعلام وحطّ الاسم ده مكان
   `<الجدول>` (في الموضعين):
```sql
insert into public.<الجدول>
select (jsonb_populate_record(
          null::public.<الجدول>,
          e || jsonb_build_object('updated_at', coalesce(e->>'updated_at', now()::text)))).*
  from jsonb_array_elements($1::jsonb) e;
```
3. `Options → Add option → Query Parameters`:
```
{{ [ JSON.stringify($input.all().map(i => i.json)) ] }}
```
4. `Settings` → فعّل **Execute Once** و**Always Output Data**.

## التأكيد بعد كل فرع
شغّل الوركفلو، وبعدها على القاعدة:
```sql
select 'stock_<فرع>' t, count(*), max(updated_at) at time zone 'Africa/Cairo'
  from public.stock_<فرع>;
```
لازم العدد يبقى صح والتاريخ النهاردة، و`stock_<فرع>_staging` يكون **اختفى**.
وأقوى تأكيد إن الـview اترِبطت صح: عدد صفوف `v_stock_units_full`
يساوي مجموع الأربع جداول بالظبط.

## ملاحظة
العقدتين في الفرع الواحد بيكتبوا على **نفس** جدول الـstaging وبيشتغلوا
مع بعض — مفيش تعارض لأن كل واحدة بتجيب صفوف مختلفة (دوا / مش دوا).

## ⚠️ فخ: `select x.*` بيلغي القيم الافتراضية للأعمدة

النسخة الأولى من الاستعلام كانت `select x.* from jsonb_populate_recordset(...)`.
دي **بتدرج NULL صراحةً** لأي عمود مش موجود في الـJSON — والإدراج
الصريح بيتخطّى `DEFAULT` بتاع العمود.

**اللي حصل**: مدخلات عقدة الدواء مفيهاش `updated_at` خالص. العقدة
القديمة (`Map Each Column Manually`) كانت بتسيب العمود فياخد
`default now()`. الاستعلام الجديد حطّ NULL، فـ`stock_san.updated_at`
بقى **NULL في كل الصفوف** بعد ما العقدتين اتحوّلوا.

**وده خطير**: `updated_at` هو اللي بنقيس بيه إن الفرع لسه بيتحدّث —
وهو أساس أي تنبيه على التجمّد. العدد كان صح والـview مطابقة،
فالعطل كان **ساكت تمامًا**.

**العلاج** (في الاستعلام فوق): `jsonb_build_object` بيحط `now()`
لما المفتاح ناقص، فالعمود بيتملا سواء eplus بعته أو لأ.

**الدرس العام**: أي `insert ... select` بيبني الصف من JSON لازم
تتأكد إن كل عمود له `DEFAULT` إما جاي في الـJSON أو متحطّ صراحةً —
وإلا الافتراضي بيتلغي من غير ما حد ياخد باله.
