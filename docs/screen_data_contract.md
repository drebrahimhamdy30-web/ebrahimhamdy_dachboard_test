# عقد البيانات لأي شاشة — سقف الـ1000 صف

> اقرا ده قبل ما تكتب أي شاشة جديدة أو تعدّل نداء بيانات في شاشة قديمة.

## القاعدة في سطر واحد
**أي شرط المستخدم بيختاره لازم يوصل للسيرفر. المتصفح وظيفته يعرض، مش يفلتر.**

## ليه
PostgREST بيقص أي رد عند **1000 صف** (`db-max-rows`)، والقص بيحصل **بعد**
`WHERE` و`ORDER BY`:

```
كل الصفوف → WHERE (شروط الـURL) → ORDER BY → LIMIT 1000 → المتصفح → .filter()
                    ↑ بتشوف كل الصفوف                        ↑ بتشوف اللي وصل بس
```

يعني لو الشاشة جابت «الكل» وفلترت في المتصفح، أي صف وقع برّه الألف **مش
موجود** — من غير خطأ ومن غير تحذير. ده اللي خفى ٣ طلبات تحويل معلّقة من
مايو/يوليو/أغسطس (ترتيبهم ٥ و٧ و٩ آلاف) عن شاشة التحويلات شهور.

و`limit=5000` **وهم**: اتجرّب على `customers` (21,356 صف) فرجّع 1000 بالظبط.

## الأدوات (موجودة في `session.js`، يعني متاحة في كل شاشة)

| الأداة | امتى تستعملها |
|---|---|
| `Session.getAll(path, {label})` | لما النتيجة **بعد الفلترة** ممكن تعدّي 1000 — بتلفّ بالـoffset وترجّع `rows.total` و`rows.incomplete` |
| `Session.rpcAll(fn, body, {query,label})` | دالة RPC بترجّع **صفوف** (setof/table). الفلاتر بتتطبّق على ناتج الدالة، فمابنعدّلش الدالة نفسها |
| `Session.count(path)` | عايز **رقم** بس (عدّادات/بادچات) — أرخص وأسرع من جلب الصفوف والعدّ في المتصفح |
| `Session.dataWarn(msg)` | تحذير مرئي للمستخدم إن البيانات ناقصة |

دالة RPC بترجّع **`jsonb`** (صف واحد) **مش متأثرة بالسقف أصلًا** — وده الشكل
المفضّل لأي شاشة فيها مجاميع أو حسابات (زي `get_open_transfers` و`get_stock_summary`).

## اختيار الشكل الصح

| الحالة | الصح |
|---|---|
| النتيجة بعد الفلتر أقل من ~1000 (أغلب الشاشات) | ابعت الشرط في الـURL وخلاص |
| النتيجة نفسها كبيرة، والشاشة بتعرض قايمة | ترقيم من السيرفر: `limit` + `offset` + العدد الحقيقي |
| محتاج مجاميع/إحصائيات على كل البيانات | الحساب في القاعدة (RPC بترجّع `jsonb`) — مش تسحب وتجمع في المتصفح |
| عدّاد/بادچ | `Session.count()` |

## الحارس
`node scripts/check-fetch-limits.js` بيمشي مع كل commit (`.githooks/pre-commit`)
وبيرفض:
- نداء على جدول كبير من غير ترقيم ولا فلتر ضيق
- `limit` أكبر من 1000 (وهم)
- نداء لدالة RPC بترجّع صفوف من غير ترقيم
- `.from(...).select(...)` من غير تضييق

لو النداء آمن فعلًا (جدول إعدادات صغير مثلًا) حطّ على السطر:

```js
// data-ok: السبب
```

وفيه كمان **حارس وقت التشغيل**: أي رد من `/rest/v1/` رجع 1000 صف بالظبط
ونداؤه ماطلبش `limit` بيطلّع شريط أحمر فوق الشاشة للمستخدم.

## قالب نداء نموذجي

```js
// قايمة كبيرة: الشرط في السيرفر + لفّ آمن
const rows = await Session.getAll(
  'orders?select=id,bill_no,status&branch_id=eq.' + branchId +
  '&bill_date=gte.' + fromISO + '&order=bill_date.desc',
  { label: 'طلبات الفرع' });
if (rows.incomplete) { /* الشاشة عرفت إن فيه نقص */ }

// عدّاد
const pending = await Session.count('orders?select=id&status=eq.pending');

// دالة بترجّع صفوف
const items = await Session.rpcAll('get_shortages', { p_branch: branch }, { label: 'النواقص' });
```
