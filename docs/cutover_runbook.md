# دليل يوم التحويل

**من:** سحابة Supabase → **إلى:** `supabase.ebrahimhamdy.com`
**اتكتب:** 2026-09-20 · بعد بروفة كشفت بندين ماكانوش في الحسبان

---

## الترتيب — مش اختياري

```
1. تجميد السحابة      → كرونات + n8n يقفوا
2. cutover.sh go       → مزامنة أخيرة + فك العزل + كرونات السيرفر
3. n8n → السيرفر       → كريدنشيال + روابط + ختم التوكن
4. switch-backend.sh   → الشاشات وتطبيق الطيار
5. متابعة ساعة
```

**ليه الترتيب ده:** أي داتا تدخل السحابة **بعد** المزامنة الأخيرة بتضيع. وأي إشعار يتبعت من السحابة **والسيرفر شغّال** = الطيار ياخده مرتين.

## الخطوات

### 1) تجميد السحابة

**كرونات السحابة** (من SQL Editor على السحابة):
```sql
do $$ declare r record; begin
  for r in select jobid from cron.job where active loop
    perform cron.alter_job(r.jobid, active := false);
  end loop;
end $$;
select count(*) filter (where active) as "لسه شغّالة" from cron.job;   -- لازم 0
```

**n8n:** وقّف كل الـworkflows النشطة (Active → off).

### 2) السيرفر

```bash
/root/phalix-repo/scripts/cutover.sh go
```
بيعمل: مزامنة أخيرة (بيانات + حسابات) · فك عزل ٥ تريجرات · تشغيل ١٢ كرون من `cloudsrc.v_migration_post` بعنوان السيرفر · تحقق.

### 3) n8n — أكبر بند يدوي

> ⚠️ **البند ده اتكشف في البروفة ومكانش في أي قايمة قبلها.**
> تطبيق الطيار **مش** بيدخل من سوبابيز — بيدخل من ويبهوك n8n، واللي
> بيوقّع التوكن **بختم السحابة**. السيرفر ختمه مختلف فبيرفض التوكن
> بـ401، والتطبيق بيقول «لم يتم العثور على بيانات السائق» — رسالة
> بتوديك في اتجاه غلط تمامًا.

| الحاجة | مكانها | تتغيّر لإيه |
|---|---|---|
| كريدنشيال `Supabase account` | Credentials | رابط + مفتاح service_role بتاع السيرفر |
| كريدنشيال Postgres | Credentials | `db` port `5432` (بعد `docker network connect`) |
| روابط عقد HTTP | جوّه كل عقدة (`Verify Login` · `Insert Session` · `إنشاء رمز الاستعادة` · …) | `https://supabase.ebrahimhamdy.com` |
| الختم في `Generate JWT` و `Generate Token` | **مكتوب صريح في الكود** | `JWT_SECRET` بتاع السيرفر (من `.env`) |

```bash
docker network connect supabase_default n8n    # مرة واحدة — بعدها n8n يشوف القاعدة باسم db
```

**اتأكد قبل ما تكمّل:** سجّل دخول بحساب طيار تجريبي من التطبيق. لو طلعت «لم يتم العثور على بيانات السائق» يبقى الختم لسه غلط.

### 4) الشاشات والتطبيقات

```bash
./scripts/switch-backend.sh server     # على جهازك مش السيرفر
```
بيغيّر `config.js` في الريبوهين + `app-config.json`، وبيتأكد إن السيرفر رادّ 200 قبل ما يكتب حاجة.

**تطبيق الطيار:** البناء 71 فأعلى بيقرا `app-config.json` عند كل فتح. النسخ الأقدم **مابتقراش الملف** وهتفضل على السحابة المتجمدة — فلازم تنشر التحديث:

```sql
update driver_app_version set version_code = 71,
  version_name = 'poll-v71', force_update = true,
  apk_url = 'https://github.com/drebrahimhamdy30-web/phalix-driver-app/releases/download/v71/phalix-driver.apk'
where id = 1;
```

## تفاصيل n8n — مجرّبة فعليًا (بروفة 2026-09-20)

عملنا **نسخة** من ورك فلو الدخول ووجّهناها للسيرفر وجرّبناها بـcurl — والأصلي مالتمسش والطيارين شغّالين طول الوقت. النتيجة: الدخول اشتغل، والسيرفر قبل التوكن، ورجّع بيانات السائق.

دي الأخطاء اللي قابلتنا بالترتيب — كل واحدة رسالتها كانت **بتودّي في اتجاه تاني**:

| العرض | السبب الحقيقي |
|---|---|
| `401 — Expected 'Basic' authentication scheme` | الرابط ناقصه `/rest/v1` فوقع على مسار لوحة التحكم. **بدّل الدومين بس وسيب المسار كامل** |
| `Invalid URL ... must start with http` | الرابط اتكتب من غير `https://` |
| `401 — Unauthorized` (من غير تفاصيل) | مفتاح service_role في الكريدنشيال ناقص — اتقص وقت النسخ (١٨٠ حرف) |
| `401 — PGRST301 None of the keys was able to decode the JWT` | عقدة `Generate Token` لسه بتوقّع بختم السحابة |
| `Couldn't connect with these settings` في الكريدنشيال | **تجاهلها** — n8n بيختبر على `/rest/v1/` والسيرفر بيرفضه بـ403 RBAC. العقد الحقيقية بتشتغل عادي |

**الترتيب اللي ينفع:** الروابط → الكريدنشيال → الختم، وبعد كل خطوة شغّل الاختبار. وتبويب `Executions` في n8n بيوريك العقدة الحمرا ورسالتها — أسرع من أي تخمين.

**العقد اللي لازم تتغيّر في الأصلي يوم التحويل:**

| المسار | العقد |
|---|---|
| `login` | `Verify Login` (رابط + كريدنشيال) · `Insert Session` (رابط + كريدنشيال) · `Generate Token` (الختم) |
| `verify_token` | `HTTP Request` (رابط + كريدنشيال) · `Generate JWT` (الختم) |
| `forgot_password` | `إنشاء رمز الاستعادة` (رابط + كريدنشيال) |

**أمر الاختبار بعد كل تغيير** (من السيرفر، بحساب طيار تجريبي):

```bash
cd /root/supabase-project && U='USERNAME' && P='PASSWORD' && \
R=$(curl -s -X POST https://agent.ebrahimhamdy.com/webhook/login \
     -H 'Content-Type: text/plain' -d "{\"user\":\"$U\",\"pass\":\"$P\"}") && \
ID=$(printf '%s' "$R" | grep -o '"id":[0-9]*' | head -1 | cut -d: -f2) && \
JWT=$(printf '%s' "$R" | grep -o '"jwt":"[^"]*"' | cut -d'"' -f4) && \
AK=$(grep -m1 '^ANON_KEY=' .env | cut -d= -f2- | tr -d '"\r') && \
curl -s -o /dev/null -w 'HTTP %{http_code}\n' -H "apikey: $AK" \
  -H "Authorization: Bearer $JWT" \
  "https://supabase.ebrahimhamdy.com/rest/v1/drivers?branch_user_id=eq.$ID&select=id&limit=1"
```

لازم يطلع **200**.

## 🔴 التطبيق مابيتعاملش مع 401

توكن n8n صلاحيته **٧ أيام** (`exp = now + 7*24*60*60` في `Generate Token`). يعني بعد التحويل كل طيار معاه توكن قديم موقّع بختم السحابة، والسيرفر هيرفضه.

**والتطبيق مفيهوش أي معالجة للـ401** — الخروج بيحصل بس لما المستخدم يدوس «خروج» بإيده. النتيجة: الشاشة تفضل فاضية والطيار مش فاهم ليه.

**وأسوأ تفصيلة:** الإشعارات هتفضل شغّالة (السحب بيستعمل `appSecret` مش التوكن) — فالطيار يسمع التنبيه، يفتح التطبيق، ويلاقي مفيش طلبات. ده أسوأ من إن التطبيق يقع، لأنه بيبان شغّال وهو مش شغّال.

**حلّين:**

| | |
|---|---|
| **الأفضل — بناء 72** | أي نداء يرجّع 401 → امسح الجلسة وودّي الطيار لشاشة الدخول. التحويل ساعتها بيتم لوحده |
| البديل | تبلّغ ٤٠ طيار يعملوا خروج ودخول وقت التحويل — تنسيق في أسوأ وقت |
